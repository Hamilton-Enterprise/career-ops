# Arquitetura

O núcleo do projeto é composto por scripts Node em ficheiros `.mjs`, modos em Markdown e dados do utilizador resolvidos através de `CAREER_OPS_ROOT`, `CAREER_OPS_DATA_DIR` ou do diretório do repositório. A aplicação web vive em `web/` e usa Next.js, React e TypeScript. As rotas em `web/src/app/` carregam dados e expõem APIs locais; os componentes em `web/src/components/` apresentam e alteram esse estado; os helpers em `web/src/lib/` preservam contratos partilhados. O assistente chama agentes instalados no computador através da linha de comandos. Estados, identificadores, envelopes de ação e valores persistidos permanecem canónicos em inglês; a interface e o texto produzido nesta instalação usam português de Portugal.

O checkout canónico é `~/Developer/career-ops`, os dados persistentes vivem em `~/Developer/career-ops-data` e a aplicação instalada é `~/Applications/Career Ops.app`. As worktrees são superfícies temporárias de desenvolvimento. O remote `origin` aponta para `https://github.com/Hamilton-Enterprise/career-ops.git` e `upstream` para `https://github.com/career-ops-hq/career-ops.git`; `main` é o produto operacional testado e segue `origin/main`. As alterações oficiais entram por `sync/upstream-YYYY-MM-DD`, testes e PR interno antes de chegar a `main`.

O marcador versionado `.career-ops-managed` identifica esta distribuição pela existência, sem interpretar conteúdo. O updater mantém-se self-loading; `check` devolve `managed-distribution` com a versão local e `update_method: sync-branch` antes do motor de estado upstream, e `apply` recusa depois de validar o checkout e antes de resolver alvos, consumir marcadores de reexecução, obter estado Git, criar locks ou escrever. Check e apply iniciados numa worktree marcada permanecem nessa origem para não contornar a política através de um main sem marcador. O rollback conserva o percurso anterior.
